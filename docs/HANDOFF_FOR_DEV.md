## 1. 서비스 개요

헬스장(센터) 안에서 **정해진 시각에 안내 방송이 자동으로 나가게** 하는 웹 서비스입니다.
프런트 데스크의 PC 한 대가 「송출 화면」을 띄워 두면, 예약한 요일·시각에 맞춰 안내 음성이 스피커로 나갑니다.

담당자는 관리 화면에서 방송 문구를 쓰고, 목소리를 고르고, 언제 나갈지 예약합니다.

### 1.1 화면 목록

| 화면 | 파일 | 하는 일 |
|---|---|---|
| 관리 화면 | `index.html` | 목소리 고르기, 방송 만들기·고치기·지우기, 예약, 즉시 송출, 송출 이력 |
| 송출 화면 | `onair.html` | 프런트 PC에 띄워 두는 화면. 예약 시각을 지켜보다 자동으로 방송을 내보낸다 |
| PC 앱 내려받기 | `download.html` | 데스크톱 앱 설치 파일 안내 (§6 참고) |

### 1.2 기능 명세

**목소리 고르기**
- 고를 수 있는 목소리는 **4명 고정**입니다: 아라 / 민영 / 종현 / 신우.
- 관리 화면 맨 위 「방송 목소리」에서 문안 3종 중 하나를 골라 네 목소리를 들어본 뒤 하나를 선택합니다. 고르는 즉시 저장됩니다.
- 여기서 고른 값이 **그 센터의 기본 목소리**입니다.
- 속도·톤·성별 선택 UI는 **의도적으로 없습니다.** 담당자가 고르는 축은 «화자 4명 중 하나» 하나뿐입니다.
  엔진에는 속도·톤이 항상 기본값(0)으로 넘어갑니다.

**방송 CRUD**
- 「+ 새 방송」으로 만들고, 목록 카드의 「수정」·「삭제」로 고치고 지웁니다.
- 카드의 토글로 방송을 켜고 끌 수 있습니다. 꺼진 방송은 예약 시각이 와도 나가지 않습니다.
- 방송 하나마다 목소리를 따로 지정할 수 있습니다. 지정하지 않으면 **센터 기본 목소리를 따릅니다.**
  편집 화면에 어느 쪽인지 한 줄로 표시됩니다 («센터 기본 목소리 사용 중 — 아라 · 여성 · 차분한 상담·안내 톤»).

**예약 규칙**

| 종류 | 값 | 동작 |
|---|---|---|
| `weekly` (반복) | 요일 여러 개 + 시각 여러 개 | 고른 요일의 고른 시각마다 매주 반복 |
| `once` (1회성) | 날짜 1개 + 시각 1개 | 그 날짜·시각에 한 번만. 지나가면 다시 안 나감 |
| `none` (예약 없음) | — | 자동으로는 안 나감. 「즉시 송출」로만 사용 |

- 예약 판정은 **분 단위**입니다. 같은 방송이 같은 분에 두 번 나가지 않도록 «이미 내보낸 표»를 따로 둡니다.
- 송출 화면을 켜 둔 동안에만 예약이 동작합니다. 브라우저 탭이 닫히면 방송도 멈춥니다.

**즉시 송출** — 목록 카드의 「즉시 송출」을 누르면 예약과 무관하게 그 자리에서 나갑니다. 이력에 «즉시 송출»로 기록됩니다.

**센터별 분리** — 상단 드롭다운으로 센터를 바꿉니다. 방송 목록·기본 목소리·송출 이력이 모두 센터별로 나뉩니다.

**반복 재생 기능은 없습니다.** 방송은 항상 한 번만 읽습니다.

## 2. 데이터 모델

프로토타입은 브라우저 `localStorage` 에 저장합니다. 실서비스에서는 이 구조를 그대로 서버 DB로 옮기면 됩니다.

저장 키: `ngym_bcast_v1` (본체) · `ngym_bcast_log_v1` (송출 이력) · `ngym_bcast_fired_v1` (중복 송출 방지)

### 2.1 Center (센터)

| 필드 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | string | 필수, 고유 | 센터 식별자 |
| `name` | string | 필수 | 화면에 보이는 센터 이름 |
| `defaultVoice.speaker` | SpeakerId | 필수 | 이 센터의 기본 목소리. §2.4 의 4개 값 중 하나 |

### 2.2 Broadcast (방송)

| 필드 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `id` | string | 필수, 고유 | 방송 식별자 |
| `centerId` | string | 필수, Center.id 참조 | 어느 센터의 방송인지 |
| `name` | string | 필수, 1~40자 | 방송 이름 |
| `script` | string | 필수 | 읽을 대본. 길이 제한 없음 |
| `enabled` | boolean | 필수 | 꺼짐이면 예약 시각이 와도 안 나감 |
| `voice.speaker` | SpeakerId \| `''` | 필수 | `''` = 센터 기본 목소리를 따름 |
| `schedule` | Schedule | 필수 | §2.3 |

> 대본은 서버로 보내기 전에 **문장 단위로 쪼갭니다** (한 덩어리 최대 80자 기준, `splitScript()`).
> 긴 문장을 한 번에 합성시키면 응답이 느리고 중간에 끊기기 때문입니다. 쪼갠 덩어리를 순서대로 이어서 재생합니다.

### 2.3 Schedule (예약)

| 필드 | 타입 | 제약 | 설명 |
|---|---|---|---|
| `type` | `'weekly'` \| `'once'` \| `'none'` | 필수 | 예약 종류 |
| `days` | number[] | `weekly` 일 때 1개 이상 | 요일. 0=일 … 6=토 |
| `times` | string[] | `weekly` 일 때 1개 이상 | `"HH:MM"` 24시간 표기 |
| `date` | string | `once` 일 때 필수 | `"YYYY-MM-DD"` |
| `time` | string | `once` 일 때 필수 | `"HH:MM"` |

### 2.4 Voice (목소리 설정)

고를 수 있는 값은 아래 4개뿐입니다. 이 표의 정본은 `core.js` 의 `SPEAKERS` 배열 한 곳입니다.

| SpeakerId | 이름 | 성별 | 톤 |
|---|---|---|---|
| `nara_call` | 아라 | 여성 | 차분한 상담·안내 톤 (기본값) |
| `nminyoung` | 민영 | 여성 | 밝고 높은 톤 |
| `njonghyun` | 종현 | 남성 | 부드러운 중저음 |
| `nsinu` | 신우 | 남성 | 낮고 묵직한 톤 |

`SpeakerId` 값은 **클로바보이스의 화자 코드와 같습니다.** 서버에서 변환할 필요가 없습니다.

### 2.5 LogEntry (송출 이력)

| 필드 | 타입 | 설명 |
|---|---|---|
| `ts` | number | epoch ms |
| `day` | string | `"YYYY-MM-DD"` |

| `centerId` / `bid` / `name` | string | 센터·방송 식별자와 이름 |

## 3. 서버가 제공해야 할 API

**필수는 `POST /tts` 하나뿐입니다.** 나머지는 권장 사항입니다.
`config.js` 의 `ttsApiBase` 에 적은 주소가 아래 경로들의 앞머리가 됩니다.
(예: `ttsApiBase = 'https://tts.example.com'` → 실제 호출은 `https://tts.example.com/tts`)
서버가 `/api/tts` 처럼 앞에 경로를 두고 있다면 `ttsApiBase` 를 `https://tts.example.com/api` 로 적으면 됩니다. 어댑터를 고칠 필요가 없습니다.

### 3.1 `POST /tts` — 음성 합성 (필수)

요청 `Content-Type: application/json`

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `text` | string | ✅ | 읽을 문구. 이미 문장 단위로 쪼개져 옵니다 |
| `speaker` | string | ✅ | §2.4 의 SpeakerId. 클로바 화자 코드와 동일 |
| `speed` | number | | -5 ~ 5. 클수록 느림. 이 서비스는 항상 `0` |
| `pitch` | number | | -5 ~ 5. 이 서비스는 항상 `0` |
| `volume` | number | | 0 고정 |
| `format` | string | | `"mp3"` 고정 |

```json
{ "text": "회원님께 안내 말씀 드립니다.", "speaker": "nara_call", "speed": 0, "pitch": 0, "volume": 0, "format": "mp3" }
```

성공 응답 — 아래 둘 중 **아무거나** 쓰면 됩니다. 어댑터가 둘 다 받습니다.

- `200 audio/mpeg` + mp3 바이너리 본문 ← **권장**
- `200 application/json` + `{ "audioUrl": "https://..." }` (프런트가 그 주소를 받아 재생)

실패 응답 — HTTP 상태코드는 4xx/5xx, 본문은 JSON

```json
{ "error": "quota_exceeded", "message": "이번 달 음성 사용량을 모두 썼습니다." }
```

| 필드 | 설명 |
|---|---|
| `error` | 기계가 읽는 코드. 자유롭게 정하되 아래 예시를 권장 |
| `message` | **사용자 화면에 그대로 뜨는 한국어 문장.** 기술 용어 없이 써 주세요 |

권장 `error` 코드: `bad_request` (필드 누락·화자 코드 오류) · `unauthorized` (인증 실패) ·
`quota_exceeded` (무료 한도 초과) · `upstream_error` (클로바 호출 실패) · `rate_limited` (호출 과다)

> 실패해도 서비스가 멈추지 않습니다. 프런트는 자동으로 브라우저 기본 음성으로 내려가 방송을 내보내고,
> `message` 를 화면에 띄웁니다. 그래도 **방송은 나갑니다.**

#### CORS — 관리 화면과 서버가 다른 도메인이면 필수

프런트는 `Content-Type: application/json` 으로 POST 합니다. 이 헤더 때문에 브라우저가 **본 요청 전에 `OPTIONS` 예비 요청(preflight)을 먼저 보냅니다.**
서버가 `OPTIONS` 에 응답하지 않으면 «네트워크 오류»만 뜨고 원인이 보이지 않습니다. 처음 붙일 때 가장 많이 걸리는 지점입니다.

서버가 관리 화면과 **다른 도메인**에 있다면 아래를 처리해 주세요.

| 항목 | 값 |
|---|---|
| `OPTIONS /tts` | `204` 로 응답 |
| `Access-Control-Allow-Origin` | 관리 화면 도메인 (`*` 는 피하세요) |
| `Access-Control-Allow-Methods` | `POST, GET, OPTIONS` |
| `Access-Control-Allow-Headers` | `Content-Type` (인증 헤더를 쓰면 `, Authorization` 추가) |
| `Access-Control-Allow-Credentials` | 세션 쿠키 인증(§3.3 의 1번)을 쓸 때만 `true` |

**같은 도메인에 올리면 이 설정이 전부 필요 없습니다.** §3.3 에서 1번 방식을 권하는 이유이기도 합니다.

### 3.2 `GET /health` — 서버 상태 확인 (권장)

앱이 시작할 때 한 번 호출해 «지금 고품질 음성을 쓸 수 있는지»를 판단합니다.
이 엔드포인트가 없거나 실패하면 앱은 데모 음성 모드로 동작합니다. 서비스는 계속 돌아갑니다.

```json
{
  "configured": true,
  "speakers": [
    { "code": "nara_call",  "name": "아라", "gender": "female", "desc": "차분한 상담·안내 톤" },
    { "code": "nminyoung",  "name": "민영", "gender": "female", "desc": "밝고 높은 톤" },
    { "code": "njonghyun",  "name": "종현", "gender": "male",   "desc": "부드러운 중저음" },
    { "code": "nsinu",      "name": "신우", "gender": "male",   "desc": "낮고 묵직한 톤" }
  ]
}
```

`configured` 가 `false` 이거나 `speakers` 가 비어 있으면 «열쇠가 아직 안 꽂혔다»로 보고 데모 음성 모드가 됩니다.

### 3.3 인증 방식 (권장안)

이 서비스는 **센터 직원만 쓰는 내부 도구**입니다. 공개 인터넷에 열어 두면 남이 무료 한도를 소진시킬 수 있습니다.
난이도 순으로 세 가지를 권합니다. 최소 하나는 꼭 적용해 주세요.

1. **같은 도메인에 올리고 세션 쿠키로 보호** ← 가장 권장.
   기존 엔짐 서버에 `/tts` 를 얹고, 로그인된 직원 세션만 통과시킵니다. 프런트 코드 수정이 필요 없습니다.
2. **고정 토큰 헤더.** `Authorization: Bearer <토큰>` 을 요구합니다.
   이 경우 `tts-adapter.js` 의 `serverTts.synthesize()` 에 헤더 한 줄을 추가하면 됩니다 (`TODO(handoff)` 주석 위치).
   단, 토큰이 브라우저에 노출되므로 짧은 만료·재발급과 함께 쓰세요.
3. **CORS + Origin 제한 + 호출량 제한.** 허용 Origin 을 관리 화면 도메인으로 좁히고,
   IP 당 분당 호출 수를 제한합니다. 위 1·2와 함께 쓰는 보조 수단으로 보세요.

> ⚠️ 클로바 Client ID/Secret 은 **절대 프런트엔드로 내려보내지 마세요.** 서버 안에만 두고, 프런트는 `/tts` 만 부릅니다.
> 현재 프로토타입 코드·저장소 어디에도 실제 키는 들어 있지 않습니다.

### 3.4 방송·예약 저장용 API (선택)

프로토타입은 브라우저에 저장하므로 **PC 를 바꾸면 설정이 사라지고, 센터끼리 설정을 공유하지 못합니다.**
여러 센터를 한 곳에서 관리하려면 아래 API 를 추가하고 `localStorage` 대신 쓰면 됩니다. 데이터 구조는 §2 그대로입니다.

| 메서드 | 경로 | 요청 | 응답 | 설명 |
|---|---|---|---|---|
| GET | `/centers` | — | `Center[]` | 센터 목록 |
| PATCH | `/centers/{id}` | `{ defaultVoice: { speaker } }` | `Center` | 센터 기본 목소리 변경 |
| GET | `/broadcasts?centerId=` | — | `Broadcast[]` | 그 센터의 방송 목록 |
| POST | `/broadcasts` | `Broadcast` (id 없이) | `Broadcast` | 방송 생성 |
| PUT | `/broadcasts/{id}` | `Broadcast` | `Broadcast` | 방송 수정 |
| DELETE | `/broadcasts/{id}` | — | `204` | 방송 삭제 |
| GET | `/logs?centerId=&day=` | — | `LogEntry[]` | 송출 이력 조회 |
| POST | `/logs` | `LogEntry` | `201` | 송출 기록 남기기 |

에러 응답 형식은 §3.1 과 같게 맞춰 주세요 (`{ error, message }`).

## 4. 클로바보이스 Premium 연동

서버 안에서 네이버 클라우드 플랫폼의 CLOVA Voice Premium 을 호출합니다.

**엔드포인트**

```
POST https://naveropenapi.apigw.ntruss.com/tts-premium/v1/tts
```

**요청 헤더**

| 헤더 | 값 |
|---|---|
| `X-NCP-APIGW-API-KEY-ID` | 발급받은 Client ID |
| `X-NCP-APIGW-API-KEY` | 발급받은 Client Secret |
| `Content-Type` | `application/x-www-form-urlencoded` |

> 🔑 **발급된 Client ID / Secret 은 담당자(형)에게 별도 전달받으세요.** 이 문서와 저장소에는 키가 들어 있지 않습니다.
> 받은 키는 서버의 환경변수(예: `CLOVA_CLIENT_ID`, `CLOVA_CLIENT_SECRET`)로만 두고 코드에 적지 마세요.

**요청 파라미터** (form-urlencoded)

| 이름 | 값 | 설명 |
|---|---|---|
| `text` | 읽을 문구 | 필수. UTF-8 |
| `speaker` | `nara_call` \| `nminyoung` \| `njonghyun` \| `nsinu` | 필수. 프런트가 보낸 `speaker` 를 그대로 넘기면 됩니다 |
| `speed` | `-5` ~ `5` | 클수록 느림. 이 서비스는 `0` |
| `pitch` | `-5` ~ `5` | 이 서비스는 `0` |
| `volume` | `-5` ~ `5` | `0` |
| `format` | `mp3` \| `wav` | `mp3` |

**응답** — 성공하면 `200` 과 함께 오디오 바이너리가 본문으로 옵니다. 그대로 프런트에 흘려보내면 됩니다.

**화자 코드 후보** — 이 서비스가 쓰는 4명은 위 표대로입니다.
클로바 Premium 에는 안내 방송에 쓸 만한 화자가 더 있습니다 (`nes_c_hyeri`, `nes_c_sohyun`, `nes_c_mikyung`, `ntaejin` 등).
다만 **화면에서 고를 수 있는 목소리를 늘리려면 `core.js` 의 `SPEAKERS` 표와 미리듣기 mp3 를 함께 추가해야 합니다.**
화자를 바꾸기 전에 담당자와 상의해 주세요. 아동 화자는 사용하지 않기로 되어 있습니다.

**curl 예시**

```bash
curl -X POST 'https://naveropenapi.apigw.ntruss.com/tts-premium/v1/tts' \
  -H "X-NCP-APIGW-API-KEY-ID: $CLOVA_CLIENT_ID" \
  -H "X-NCP-APIGW-API-KEY: $CLOVA_CLIENT_SECRET" \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'text=회원님께 안내 말씀 드립니다. 잠시 후 안내 방송이 시작됩니다.' \
  --data-urlencode 'speaker=nara_call' \
  --data-urlencode 'speed=0' \
  --data-urlencode 'pitch=0' \
  --data-urlencode 'volume=0' \
  --data-urlencode 'format=mp3' \
  --output sample.mp3
```

성공하면 `sample.mp3` 가 생깁니다. 틀어서 소리가 나면 연동 준비가 끝난 것입니다.

**서버 쪽 `/tts` 구현 요약**

1. 요청 본문에서 `text`, `speaker`, `speed`, `pitch` 를 꺼낸다.
2. `speaker` 가 허용된 4개 값인지 검사한다 (아니면 `400` + `{ error: 'bad_request', ... }`).
3. 캐시에 있으면 (§5) 저장된 mp3 를 그대로 돌려준다.
4. 없으면 위 클로바 엔드포인트를 호출하고, 받은 mp3 를 캐시에 넣은 뒤 `audio/mpeg` 로 돌려준다.
5. 클로바가 실패하면 상태코드와 함께 `{ error, message }` 를 돌려준다. `message` 는 한국어 안내 문장으로.

## 5. 요금과 캐싱 — 꼭 읽어 주세요

CLOVA Voice Premium 은 **월 5,000자까지 무료**이고, 그 이상은 유료 요금제로 넘어갑니다.

안내 방송은 성격상 **같은 문구를 매일 반복해서 내보냅니다.** 캐싱하지 않으면 다음과 같은 일이 벌어집니다.

> 「마감 30분 전 안내」 대본이 120자이고, 평일 매일 21:30 에 나간다고 합시다.
> 캐시가 없으면 한 달에 120자 × 22일 = 2,640자를 **같은 문장을 다시 만드느라** 씁니다.
> 방송이 5개만 돼도 무료 한도를 첫 주에 넘깁니다. 캐시를 두면 방송 5개 × 120자 = 600자로 **한 달 내내 충분합니다.**

**권장 캐싱 방식**

- **캐시 키** = `sha256(text + '|' + speaker + '|' + speed + '|' + pitch)`
  문구·화자·속도·톤이 하나라도 다르면 다른 소리이므로 네 가지를 모두 키에 넣습니다.
- **저장 위치** = 서버의 파일 시스템 또는 오브젝트 스토리지(S3 등)에 `<키>.mp3` 로 저장.
  오디오는 한 덩어리에 수십 KB 수준이라 용량 부담이 거의 없습니다.
- **만료** = 두지 않아도 됩니다. 같은 입력이면 클로바 출력도 항상 같습니다.
  대본을 고치면 키가 바뀌어 자연스럽게 새로 합성됩니다. 오래된 파일은 주기적으로 정리하는 정도면 충분합니다.
- **사용량 로그**를 함께 남기면 좋습니다. 합성한 글자 수를 월별로 더해 두면 한도 초과를 미리 알 수 있습니다.

프런트에도 같은 키 규칙의 캐시가 이미 들어 있습니다(`core.js` 의 `Cache`, IndexedDB 사용).
예약 시각 전에 미리 소리를 받아 두므로, 방송 순간에 네트워크가 흔들려도 방송이 그대로 나갑니다.
**서버 캐시와 프런트 캐시는 둘 다 필요합니다.** 프런트 캐시는 PC 한 대 안에서만 유효하기 때문입니다.

## 6. PC 데스크톱 앱

### 6.1 왜 필요한가

센터에서는 보통 **배경 음악을 틀어 둔 채로** 안내 방송을 내보냅니다.
안내가 나갈 때 음악이 그대로 깔려 있으면 말이 묻혀 들리지 않습니다.

그런데 **브라우저는 자기 탭 밖의 소리를 건드릴 수 없습니다.** 다른 앱(음악 플레이어)이나 시스템 볼륨을 제어할 방법이 없습니다.
그래서 데스크톱 앱이 따로 있습니다. 앱이 하는 일은 **하나뿐입니다.**

> 방송이 시작되면 재생 중이던 음악을 멈추고, 방송이 끝나면 다시 틀어 준다.

그 외 모든 화면과 기능은 **앱이 웹 주소를 그대로 불러서 보여 줍니다.** UI 를 두 벌 관리하지 않습니다.
웹을 고치면 앱도 같이 고쳐집니다.

### 6.2 웹 ↔ 앱 통신 규격

웹은 방송이 시작·종료될 때 브라우저 `CustomEvent` 를 발생시킵니다. 앱은 이 이벤트를 듣고 음악을 제어합니다.

| 이벤트 이름 | 언제 | `detail` |
|---|---|---|
| `nb:broadcast-start` | 방송 재생 직전 | `{ id: string, name: string }` |
| `nb:broadcast-end` | 방송 재생 완료 또는 실패 후 | `{ id: string, name: string }` |

발생시키는 쪽은 `core.js` 의 `emitBroadcast()` 한 함수입니다.

> ⛔ **`core.js` 의 `emitBroadcast('start')` / `emitBroadcast('end')` 호출을 지우지 마세요.**
> 앱은 이 신호로 음악을 멈춥니다. 브라우저에서만 쓸 때는 아무 영향이 없는 코드라 무심코 지우기 쉽습니다.

앱 쪽 동작 (현재 구현):
- 음악 앱(Apple Music, Spotify)은 **앱을 지목해서** 멈추고 되살립니다.
- 브라우저에서 나는 소리는 **미디어 키**(재생/일시정지)로 제어합니다.
- 소리가 실제로 나고 있는지 먼저 확인하고, 조용하면 아무것도 건드리지 않습니다.
- 어떤 이유로든 «되살리기»가 실패해도 **15분 뒤 자동으로 복구**하는 안전장치가 있습니다.

### 6.3 배포 방식

- 앱 소스는 **웹과 다른 저장소**에 있습니다: `yjiihwan/ngym-broadcast-desktop`
- 빌드 결과물(.exe / .dmg)은 그 저장소의 **GitHub Releases** 에 올립니다.
- 웹의 `download.html` 이 그 릴리스 파일을 내려받는 카드를 보여 줍니다.
- 버전을 올릴 때는 **`desktop-releases.js` 의 `VERSION` 한 줄**만 고치면 파일명·주소·화면 표기가 모두 따라옵니다. 용량 표기는 함께 고쳐 주세요.
- ⛔ 빌드된 바이너리를 웹 저장소에 커밋하지 마세요.

### 6.4 미완 — 개발자 몫

| 항목 | 상태 |
|---|---|
| **macOS 코드서명·공증(notarization)** | ❌ 미완. 지금은 설치할 때 «확인되지 않은 개발자» 경고가 뜹니다. Apple Developer 계정으로 서명·공증이 필요합니다. 끝나면 `desktop-releases.js` 의 `MAC_UNSIGNED_NOTICE` 를 `false` 로 바꾸면 경고 안내가 사라집니다 |
| **Windows 코드서명** | ❌ 미완. SmartScreen 경고가 뜹니다 |
| **Windows 실기기 검증** | ❌ 미검증. 음악 제어는 `keybd_event(VK_MEDIA_PLAY_PAUSE)` 방식으로 구현되어 있으나 실제 PC에서 확인하지 못했습니다 |
| **macOS 권한 안내** | ⚠️ macOS 에서 미디어 키를 보내려면 시스템 설정 → 개인정보 보호 및 보안 → **손쉬운 사용**에 앱을 등록해야 합니다. 권한 없이는 음악이 멈추지 않습니다. 설치 안내에 이 단계를 넣어 주세요 |
| **자동 업데이트** | ❌ 없음. 새 버전은 사용자가 다시 내려받아 설치합니다 |

## 9. 로컬에서 띄워 보기

빌드 과정이 없습니다. 정적 파일이라 웹 서버로 폴더를 열기만 하면 됩니다.

```bash
cd prototype
python3 -m http.server 8000
# 브라우저에서 http://127.0.0.1:8000/index.html
```

서버 주소를 설정하지 않은 상태에서도 **모든 화면과 기능이 끝까지 동작합니다.**
목소리 미리듣기는 미리 합성해 둔 mp3 가 나오고, 방송 재생은 브라우저에 설치된 음성으로 읽습니다.
화면에는 «데모 음성 — 실서비스에선 서버에서 합성됩니다» 안내가 함께 뜹니다.

서버를 띄우지 않고 실서버 연동만 잠깐 시험해 보려면 주소 뒤에 `?voice=https://내서버주소` 를 붙이면 됩니다.
